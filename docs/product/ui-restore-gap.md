# UI 还原 Gap 分析 + 优先级清单

> 产品经理产出。这是「该长什么样 vs 现在长什么样」的逐屏差距清单,**不评估新功能**,只做视觉/交互还原对比。
> 技术实现方案(动哪个组件、用什么库)不在本文档范围——那是架构窗口的事。

## 背景与一个关键现实

视觉权威源(设计稿)只覆盖 **3 份 HTML**,但它们的覆盖范围和路由的对应关系需要先澄清,否则架构会切错活:

| 设计稿 | README 声明的归属 | 实际覆盖的屏 |
|---|---|---|
| `design-v1/yujee-home2.html` | `/create` + `/my-albums` | 单页双视图:**view-home**(hero + 创作 composer + 6 features + 灵感库 + CTA + footer)和 **view-projects**(作品卡片网格)。它同时是 `/`(营销首页)、`/create`(创作入口)、`/my-albums`(作品列表)三个屏的视觉来源。 |
| `design-v1/design/editor.html` | `/album/[uuid]` | 相册编辑器(翻书式跨页阅读 + AI 对话) |
| `design-v1/design/pricing.html` | `/pricing` | 定价页 |

**澄清(请架构注意,与本单任务简报里的假设不同):**
任务简报把 `/create`、`/my-albums` 列为"缺设计稿"。**这不准确**——`yujee-home2.html` 里的 **composer**(创作输入框)就是 `/create` 的设计意图,**projects-grid**(作品卡片网格)就是 `/my-albums` 的设计意图。这两个屏**有设计参考**,只是和 home 共用一份 HTML。真正缺设计稿的是:`/credits`、`/settings`、`/login`、`/register`、`/privacy`、`/terms`。

`/admin/*` 后台不在还原范围。

## 🔴 跨屏系统性差距(最高优先,影响所有登录后屏幕)

这是本次还原**最大的结构性问题**,不属于单个屏,但决定了下面每个屏的观感。当前代码库存在**两套割裂的视觉语言**:

| | 视觉语言 A「营销/token 体系」 | 视觉语言 B「朴素 serif 应用面」 |
|---|---|---|
| 用在 | `/`、`/pricing`、`/privacy`、`/terms`(走 `MarketingChrome`) | `/create`、`/my-albums`、`/album/[uuid]`、`/credits`、`/settings`、`/login`、`/register`(裸 `<main>`) |
| 标题字体 | sans 无衬线 display | `serif` 衬线 |
| 主按钮 | 黑底 `var(--fg)` pill | 紫底 `var(--accent)` pill |
| 导航 chrome | 有顶栏(brand/pricing/语言/登录/CTA)+ footer | **完全没有任何导航**——裸 main,用户进了 /create 或 /settings 后无处可去 |
| 卡片/容器 | `shadow-card` 柔和阴影圆角 | 1px 边框方框 |

**设计稿的事实**:`yujee-home2.html` 和 `editor.html` 在**每一屏**都有完整的登录态 chrome:
1. **顶栏**:brand + 语言选择器 + **credits pill(积分余额 + 套餐名)** + **用户头像下拉菜单**(头像首字母、姓名邮箱、当前套餐 + 升级按钮、管理订阅、反馈与问题、退出登录)。编辑器顶栏还有可编辑相册标题 + "已保存"脉冲徽章 + 导出 PDF 主按钮。
2. **左侧悬浮 pill 侧边栏**:毛玻璃圆角竖条,主页 / 我的项目 两个图标按钮(hover 出文字标签),是 home↔projects 的主切换器,在 pricing 设计稿里也存在。

**当前实现的事实**:登录后的应用面(create/albums/editor/credits/settings)**既没有顶栏的 credits pill + 用户菜单,也没有左侧侧边栏**。用户在这些页面看不到自己有多少积分、是什么套餐、也没有统一的导航返回主页或切换作品。这是设计与实现差距最大的地方,且直接影响转化(用户看不到积分→不知道何时该充值/升级)。

- **优先级:P0**(它同时拖累 create / editor / albums 三个核心转化屏)
- **是否需补设计稿:否**(设计稿已完整定义顶栏 + 侧边栏,直接还原即可)
- 给架构的提示:这应作为一个**共享布局组件**统一切活,而不是每屏各做一遍。

## [营销首页] (路由 `/`)

- **设计稿来源**:`design-v1/yujee-home2.html`(view-home 部分)
- **当前实现**:`app/[locale]/page.tsx` + `components/marketing/MarketingChrome.tsx`

### 当前实现差距(逐条)

1. **Hero 背景**:设计稿是一张**生成式"指纹"SVG 艺术背景**(`hero-fp`,三色渐变描边 + `feTurbulence` 噪声扭曲 + 径向遮罩淡出,带动画);当前实现只是一组静态 `radial-gradient` 色斑。观感档次差一截,设计稿的招牌视觉缺失。
2. **创作 composer 缺失**:设计稿 hero 正中是一个**可直接开始创作的 composer**(圆角大卡:内嵌"+"上传按钮 + 3 行 textarea + 底部 4 个示例提示词 chips「旅行纪念册/宝宝成长记录/毕业纪念/美食手帐」+ 圆形发送按钮)。当前首页 hero 只有一个"开始创作"按钮跳转到 `/create`,把创作入口外置了,丢了设计稿"落地即可输入"的核心体验。
3. **Features 数量**:设计稿是 **6 个** feature(01–06,带编号);当前实现只有 **3 个**。少了一半。
4. **灵感库 / cases 区块缺失**:设计稿有一个"灵感库"横向滚动展示区(`cases-section`,带"查看更多"跳 projects);当前实现**整段没有**。
5. **语言选择器**:设计稿是 6 语言下拉(中/英/日/韩/法/西);当前实现只有 中/英 两语切换。(按海外初期目标这可能是有意收敛,列为待决策,不算硬 bug。)
6. **导航形态**:设计稿用**左侧 pill 侧边栏**做 home↔projects 切换 + 顶栏;当前实现只有顶栏(MarketingChrome),无侧边栏。

- **优先级:P0**(转化漏斗第一屏)
- **是否需补设计稿:否**(home 设计稿已覆盖;但"6 语言 vs 2 语言"需用户决策,见末尾清单)

## [创作页 / Composer] (路由 `/create`)

- **设计稿来源**:`design-v1/yujee-home2.html`(hero 里的 `composer` 组件)— **有设计参考,非缺稿**
- **当前实现**:`app/create/page.tsx`(被 `[locale]/create` re-export)

### 当前实现差距(逐条)

1. **整体形态**:设计稿是一个**精致的圆角 composer 卡片**(上传按钮内联在输入框左侧、示例 chips、圆形发送键,贴 token 体系);当前实现是一个**朴素的 "Step 1" 表单**(衬线大标题 "Start a memoir" + 普通 textarea + 虚线方框 dropzone + 紫色按钮)。两者视觉语言完全不同。
2. **示例提示词 chips 缺失**:设计稿底部有 4 个一点即填的示例标签;当前实现只有 placeholder 文案,无 chips。
3. **上传交互**:设计稿是输入框内联 "+" 图标按钮;当前实现是一大块虚线 dropzone("Click to upload 3–30 images")。设计稿没有这种独立大方框。
4. **无导航 chrome**:当前页是裸 `<main>`,无顶栏/侧边栏/积分显示(见跨屏系统性差距)。
5. **文案体系**:当前是英文硬编码 "Step 1 / Your story prompt / Generate my memoir";设计稿走 i18n。(文案对接是工程活,这里只标注视觉/结构差距。)

- **优先级:P0**(转化漏斗第二屏,且差距大)
- **是否需补设计稿:否**(composer 设计已存在于 home 稿)
- 待用户决策:设计稿 composer 是"输入即跳编辑器"的一步式;当前实现是"先填表单 + 校验 ≥3 张照片再提交"。还原时**是否保留照片数量下限提示/校验**等功能性细节,设计稿没画——这是产品/架构要对齐的点,不是纯视觉。

## [相册编辑器] (路由 `/album/[uuid]`)

- **设计稿来源**:`design-v1/design/editor.html`
- **当前实现**:`app/album/[uuid]/page.tsx` + `components/album/AlbumEditor.tsx`(+ ChatPanel / PageEditPanel / PagePreview)

### 当前实现差距(逐条)

1. **核心预览形态**:设计稿中心是一本**仿真翻书**(`book`,1.414:1 跨页,左右两页对开,中缝阴影,3D `perspective` + 翻页动画 `flipper`),下方悬浮一条**毛玻璃缩略图条**(prev/next + "1 / 3" 页码指示 + 跨页缩略图)。当前实现是**一个扁平的页面缩略图网格**(`flex-wrap` 排所有页,点选加紫色 ring),**没有书的隐喻、没有跨页、没有翻页动画、没有悬浮缩略图条**。这是编辑器最大的差距。
2. **顶栏缺失**:设计稿有完整顶栏(返回箭头 + brand + 面包屑 + **可编辑相册标题** + **"已保存"脉冲徽章** + 导出 PDF 主按钮 + credits pill + 用户头像菜单)。当前实现只有一个简单 header(衬线标题 + prompt 斜体 + 导出按钮),无面包屑、无保存状态、无积分、无用户菜单、标题不可编辑。
3. **AI 对话面板**:设计稿右栏是富对话(AI 头像"己" + 副标题"和我聊聊这段回忆" + 右上章节上下文 pill;消息含**思考指示器**——三色渐变脉冲圆点 + 动态 thinking dots;AI 文字无气泡、用户消息有气泡;AI 给出的改写结果用引用卡 `ai-quote`;操作 chips「采纳/再写一版/我来改」;章节命名给 `chip-select` 多选)。当前实现 `ChatPanel` 是一个白底方框(`h-[420px]`),需进一步核对但明显没有思考指示器、引用卡、chips 这套交互语言。
4. **聊天输入框**:设计稿是 pill 圆角输入条 + 圆形发送键 + focus 紫色光晕;当前是普通框(待 ChatPanel 细节核对)。
5. **右栏宽度/布局**:设计稿 `1fr 340px` 两栏,左书右聊;当前 `1fr 360px`,左缩略图网格 + 右栏(编辑面板 paper 色块 + 聊天框上下叠)。结构不同:设计稿没有独立的"页面编辑表单面板",编辑通过点书 + 聊天完成。
6. **整体视觉语言**:设计稿满屏 token 体系 + 无衬线 display;当前用 `serif` 标题 + 米色 `paper2` 编辑块,偏"纸感 demo",和设计稿的现代杂志工具感不同。

- **优先级:P0**(转化漏斗第三屏,是产品核心体验,差距最大)
- **是否需补设计稿:否**(editor 设计稿非常完整,含动效)
- 给架构的提示:翻书 3D 动画 + 思考指示器是这屏的"灵魂",工作量大但不可省,建议拆成独立 issue。

## [定价页] (路由 `/pricing`)

- **设计稿来源**:`design-v1/design/pricing.html`
- **当前实现**:`app/[locale]/pricing/page.tsx` + `components/marketing/PricingPlans.tsx`

### 当前实现差距(逐条)

> 这屏还原度**最高**,主体结构(月付/年付切换 + 三档套餐卡 + "最受欢迎"badge + 4 个附加积分包卡 + FAQ 手风琴)都已对上。差距集中在外围氛围:

1. **背景**:设计稿 `html` 有**多重径向渐变固定背景**(绿/紫/黄三色斑 + `background-attachment: fixed`);当前实现是纯色 `--bg`,无渐变氛围。
2. **左侧 pill 侧边栏缺失**:设计稿 pricing 也带左侧悬浮侧边栏(主页/我的项目);当前用 MarketingChrome 顶栏,无侧边栏。
3. **Nav 滚动态**:设计稿 nav 初始透明、滚动后变毛玻璃(`.nav.scrolled`);当前 MarketingChrome nav 恒定毛玻璃 sticky,无滚动渐变。
4. **登录态差异**:设计稿 body 是 `logged-in`(假设带侧边栏的登录态);当前 pricing 走的是营销态顶栏。需对齐"定价页到底是登录态还是营销态"。
5. 币种 `¥` vs `$`:设计稿是中文 `¥`,当前是 `$`——这是**正确的**(海外版),不算差距。

- **优先级:P1**(转化路径相关,但还原度已高,差距是锦上添花的氛围层)
- **是否需补设计稿:否**

- **当前实现**:`app/[locale]/my-albums/page.tsx`

### 当前实现差距(逐条)

- **优先级:P1**(常用面板,差距大,但不在"下单"主路径正中)
- **是否需补设计稿:否(主体)/ 局部是**——卡片上的"生成中/失败"状态如何呈现,设计稿没画,建议补一个状态态的卡片样式(见末尾待决策)。

# 待用户决策清单(缺稿 / 需拍板)

1. **缺设计稿、需 CEO/设计补稿的屏**(按建议优先级):
   - `/credits`(积分页)— 或明确"直接复用 pricing 的 addon-card 视觉 + 应用面 chrome",可不补稿。
