# 全站西/日/法语版本 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** apps/web 全站从 en/zh 双语扩展为 en/zh/es/ja/fr 五语，覆盖路由、UI 文案、营销长文、SEO，AI 生成链路语言保持 zh/en 不变。

**Architecture:** 三阶段流水线——S（结构改造：locale 注册 + 所有翻译面拆成按语言分文件 + es/ja/fr 先用 en 占位，全程可编译可测试）→ T（三个语言代理并行填充真翻译，互不共享文件）→ V（typecheck/test/build + ICU 占位符校验 + SSR 抽查 + 翻译质量抽审）。

**Tech Stack:** Next.js App Router + next-intl 4.7.0（localePrefix: always，cookie YUJEE_LOCALE），消息目录 src/messages/*.json，营销文案 TS 模块。

## Global Constraints

- 新 locale 集合：`['en', 'zh', 'es', 'ja', 'fr']`；`defaultLocale = 'en'` 不变；`localePrefix: 'always'`、`localeDetection: false` 不变。
- 语言原生名标签：en=English、zh=中文、es=Español、ja=日本語、fr=Français，统一放 `LOCALE_LABELS`（routing.ts），全站禁止再写 `locale === 'zh' ? '中文' : 'English'` 式二元标签。
- **AI 生成语言（wire language）保持 `'zh' | 'en'`**：`packages/contracts/src/v3.ts` 的 `V3Language`、engine 的 `Language` Literal、`src/app/api/v3/albums/schema.ts` 一律不动。凡把 UI locale 映射为生成语言处（如 ChatPanel `locale === 'zh' ? 'zh' : 'en'`）保持原样——es/ja/fr 用户生成语言落到 en，属本期刻意降级；引擎侧五语 prompt 适配为后续独立项目。
- 判别规则：`=== 'zh'` 三元中，产出**用户可见文案**的才改造；产出 **wire 值**（language 字段、API body）的不动。
- 每个翻译面必须**按语言一文件**，三个语言代理不得共享任何文件。
- ICU 占位符（`{name}` 等）与字面 `\n`（多行 pre-wrap 约定）必须逐 key 保真。
- 翻译语气基准：西语用 tú（亲近消费级产品），日语用です/ます体，法语用 vous；品牌词 Yujee 不译；术语表由 en/zh 对照推导并保持全站一致。
- 验证在 `apps/web` 内跑（仓根 pnpm test 会倒在 design-agent 环境）。
